# checkie-translation

체키 성수 게임 번역(영어·일본어·중국어 간체)을 팀이 함께 진행하고 체크하는 사이트.

- 로그인해야 볼 수 있음. 팀원은 사이트에서 아이디로 가입 → 관리자가 **보기 허용 / 편집 허용**을 켬.
- 서버는 Render, 데이터는 이 저장소의 `data` 브랜치에 저장. 모든 저장이 커밋으로 남아서 누가 언제 무엇을 바꿨는지 보고 되돌릴 수 있음.

## 사용법

**게임 번역** 첫 화면 = 게임 × 언어 현황판.

- 칸마다 **가능 / 불가능** 선택. 번역이 불가능한 언어는 ‘불가능’으로 두면 체크 대상과 완료 판단에서 빠짐.
- 칸을 누르면 그 언어의 체크리스트 5단계가 나옴.

1. **게임 정보**: 컨셉·상황·말투 (게임마다 한 번)
1-1. **원문 준비 · 모든 언어 공통** (새 게임부터 적용. 이미 번역 엑셀이 있는 게임은 예전 방식 유지)
   - 원문 분석 프롬프트 복사 → AI에 PNG와 함께 보냄 → `원문 분석`·`정답 기준` 시트가 든 엑셀 올리기
   - 원문마다 고정 ID(S001…), 원문 유형, A/B/C/REVIEW 분류·근거·문화적 배경·주의점·재설계 제안, 언어별 예외(`EN:B 이유`)
   - A는 한 번에 승인, B·C·REVIEW·미분류·예외·사람이 분류를 바꾼 줄은 하나씩 승인(REVIEW는 A·B·C로 정해야 승인) → 정답 기준 확인 → **원문 확정**
   - 중복 ID가 있으면 확정 불가(FAIL). 같은 원문이 여러 줄이면 알려 주기만 함(파일마다 한 줄이면 정상)
   - 확정 뒤 원문 엑셀을 다시 올려 원문이 바뀐 줄은 언어별 번역에 ‘원문 변경’ FAIL이 붙고 승인이 풀림
   - 확정 후 언어별 번역 프롬프트에 원문표가 들어가고, 번역 엑셀은 ID 기준으로 맞춰짐(누락 개수 표시). 체크리스트는 6단계가 됨
2. **번역 엑셀**: 프롬프트 복사 → Claude에 PNG(또는 zip)와 함께 보냄 → 받은 엑셀 올리기 → 같은 PNG도 사이트에 올리기
   - 열: `파일 | 화면 | 요소 | 한국어 원문 | 日本語(또는 English·简体中文) | 비고`. 이름이 조금 달라도 찾음. 대응표·퍼즐 재설계 같은 다른 시트도 보관.
3. **검수** (원문 기준 게임은 4가지, 예전 방식 게임은 ①~③)
   - ① 자동 점검(프로그램 검사) ② 이미지 대조 ③ 독립 검수(다른 AI 결과 엑셀 올리기 → FAIL·REVIEW만 사람이 결정) ④ 사람 최종 승인
4. **확정**
5. **적용 검수**: 번역을 넣은 PNG를 `원본이름_en` / `_jp` / `_cn`으로 올림 → 나란히 보기 · 글자 대조 · 처음 보는 사람 테스트 → ‘화면 적용 완료’

각 단계의 **확인 완료** 버튼은 누가 언제 눌렀는지 남음. 다른 곳에서 이미 끝낸 단계는 ‘이미 끝났으면 완료 처리’. 언어별 **처음부터 다시**는 확인 창에서 ‘예’를 눌러야 실행됨.

### 수정 요청 메모

- 줄 옆 **메모**(또는 자료실 ‘번역 표 보기’)에 고칠 점을 적으면 게임 화면 맨 위 빨간 상자에 뜸. 남아 있으면 확정 불가.
- **보기 전용 계정도 메모를 남길 수 있음.** 그 밖의 수정은 편집 허용이 필요.
- 작성자·시간은 서버가 기록함(이름을 바꿔 적을 수 없음). 남긴 메모는 지우거나 내용을 바꿀 수 없고, ‘반영함’ 표시만 가능. 언어를 ‘처음부터 다시’ 할 때만 함께 지워짐.

### 번역 AI · 검수 AI (팀 운영 원칙)

| 언어 | 번역 | 검수 |
| --- | --- | --- |
| 영어 | ChatGPT | Claude |
| 일본어 | Claude | ChatGPT |
| 중국어(간체) | ChatGPT | Claude |

- 사이트 기본값이 이 조합임. 2단계 ‘프롬프트 보기 · 번역 AI 바꾸기’에서 바꾸면 검수 AI도 반대쪽으로 바뀜.
- 교차 검수 프롬프트에 공통 검수 기준 6가지(정확성·누락 여부·자연스러움·용어 통일·캐릭터성·게임 적합성)와 검수 AI별 중점, ‘1차 번역 판단을 따르지 않고 독립 검수’ 원칙이 들어 있음.

### 번역 프롬프트 구성 (규칙 버전 `2026.11-v5`)

번역 프롬프트는 아래 순서로 조립됨. 공통 부분은 코드 한 곳(`COMMON_TRANSLATE`, `TRANSLATE_TIPS`)에서만 고치면 모든 게임·언어에 적용.

1. **공통 지시**: 역할 · 번역 우선순위(규칙·정답 → 의미·행동 → 말투·상황 → 자연스러움 → 글자 수) · 용어 · 의미·규칙 보존 · 문체 · 형식 · 불확실 처리 · 최종 결과
2. **번역 AI별 추가 지시**: Claude(전체 문맥·일관성) / Gemini(이미지 시각 맥락·화면 역할) / ChatGPT(1:1 대응·시트 구조 엄수)
3. **게임별 정보**: 게임 정보 단계의 컨셉·상황·**게임 규칙·정답**(새 칸)·화자별 말투
4. **용어집 · 언어 규칙**(중국어는 간체·영어 참조 블록)
5. **이번 작업 · 결과물**: `번역` 시트에 `역번역` 열 추가, 언어유희처럼 기획 판단이 필요한 건 `기획 확인` 시트(대안 최대 2개)

- `기획 확인` 시트는 엑셀을 올리면 해당 줄의 기획 확인 메모로 바뀜(작성자 ‘번역 AI’) → 기획 승인 전엔 확정 불가.
- 프롬프트 첫 줄에 규칙 버전과 AI 이름이 들어가고, 올린 엑셀에도 어느 버전·어느 AI로 만들었는지 기록됨.
- 번역 AI가 쓴 역번역은 자기 번역을 설명하는 것이라 검증력이 약함. 판단 근거는 교차 검수 AI의 역번역으로 함.
- 엑셀을 다시 올려 줄 번호가 바뀌어도 수정 요청 메모는 그 문장을 따라감. 없어진 문장의 메모는 ‘이전 엑셀’ 항목으로 남음.

### 현지화 분류 (A·B·C)와 비율

번역 엑셀의 모든 줄에 번역 AI가 분류를 붙임: `현지화 분류 | 분류 근거 | 변경 방향 | 원문 규칙 유지 | 재설계 여부`.

| 분류 | 뜻 | 사이트 처리 |
| --- | --- | --- |
| A. 직접 번역 가능 | 그대로 옮겨도 똑같이 이해됨 | 일반 검수 |
| B. 의미 현지화 필요 | 그대로 옮기면 뜻이 안 통함. 규칙은 유지하고 뜻만 현지화 | 자동 점검에 ‘변경 방향 확인’ 항목으로 올라옴 |
| C. 재설계 필요 | 발음·말장난·속담 등에 기대서 번역만으로는 문제 유지 불가 | 기획 확인 메모로 자동 전환 → 기획 승인 전 확정 불가 |

- B·C는 ‘왜 직접 번역이 안 되는지’ 근거가 필수. 근거가 비어 있거나, B인데 원문 규칙 유지가 ‘불가’면 자동 점검에 걸림.
- 분류는 **언어마다** 함(같은 문장도 일본어에선 A, 영어에선 B일 수 있음).
- 2단계에 비율 막대가 나옴: 직접 / 현지화 / 재설계 / 사람 확인 필요(B+C). 번역 난이도 통계이지 품질 점수가 아님.

### 승인·검수 무결성 (진단 1·2단계, 규칙 버전 `2026.11-v8`)

- **승인·검수는 그때의 번역문에 묶임**: 사람 판정과 AI 검수 결과에 번역문 지문을 저장. 번역이 바뀌면 브라우저와 서버 둘 다 무효로 처리(서버가 지우면 ‘서버가 확인함’ 알림).
- **독립 검수 확인값**: 검수 프롬프트 표에 줄마다 4글자 확인값(ID + 원문 + 번역으로 만듦, 같은 문구라도 줄마다 다름)이 들어가고, 검수 AI가 그대로 복사해 돌려줌. 지금 번역과 확인값이 다르면 그 줄은 반영하지 않고 다시 검수.
- **같은 어구는 한 번만 검수**: 원문과 번역이 모두 같은 줄은 독립 검수 프롬프트에 한 줄로만 들어감. 그 줄의 화면 칸에 모든 위치, ‘비고(사용 횟수)’ 칸에 ‘3번 사용 (R002·R005·R030)’이 적힘. 결과는 묶인 줄 모두에 들어가고(줄마다 확인값은 따로), ‘사람이 볼 것’에서도 한 번만 보여 주고 ‘고친 번역 쓰기’·‘유지’가 함께 적용됨. 번역이 다르면 묶지 않음(‘같은 원문 다른 번역’ 점검이 따로 잡음). ‘분리 사유’를 쓴 줄은 따로 검수.
- **이미지 대조 단계 없앰**: 검수 단계는 ① 자동 점검 → ② 독립 검수 → ③ 맥락 검수 → ④ 사람 승인. 검수 완료 조건에서도 빠짐. PNG 올리기는 자료 보관용으로 선택 사항.
- **게임 이해 · 엑셀 3개 파일 (v18)**:
  - 게임 이해(① 게임 정보 안): AI가 PNG 전체 + 게임 정보로 개요(장르·진행·행동·시스템·문구가 쓰이는 상황·분위기) · 화면(진행 순서) · 캐릭터·말투 · 핵심 용어 · 질문을 정리. 항목마다 근거와 확실도(확인됨/추정/모름). 기획이 질문에 모두 답하고 ‘이해 확정’해야 번역 프롬프트가 열림(이미 번역이 있는 게임은 예외). 확정된 이해는 원문 분석·번역·개별 검수·맥락 검수·추가 대안·현지인 질문 프롬프트에 공통 기준으로 들어가고, 독립 역번역에는 안 들어감. 번역 뒤에 이해가 바뀌면 알림.
  - 화면 순서: 원문 분석·번역 엑셀에 ‘화면 순서’ 칸(화면 안 위→아래, 왼→오른쪽). 같은 문구를 합칠 때 화면별 위치·순서를 남김.
  - ① 검수 엑셀(내부, 언어별): 01 게임 이해·번역 기준 / 02 용어·표현별 검수(번역 AI의 핵심어 대응 + 용어집 + 게임 이해 용어로 두 줄 이상에 쓰인 표현을 묶음 → 묶음 판정: 일관 / 문맥상 다름(이유 확인) / 불일치 / 핵심어 대응과 실제 번역문이 어긋남, 사용처마다 화면·상황·기능·원문·번역·번역어 뜻·독립 역번역·뜻 일치 ○△×·이유, 묶음별 담당자 결정: 통일·문맥별 유지·수정 필요) / 03 줄별 검수 작업 / 부록 A~D. 결정을 채워 올리면 03 줄 결정 + 02 용어 결정(통일 → 용어집 확정 + 어긋난 줄에 수정 요청)이 함께 반영.
  - ② 현지인 검수 엑셀(언어별, 외부 전달용): 자동 분류(현지 표현 확인 · 문화·정서 · 유머·말장난 · 캐릭터 말투 · 후보 우열 미정 · 오해 가능성 · AI 판단 불일치). 상황·원문 뜻·질문을 한국어 + 그 언어로. 검수 AI가 ‘현지인 확인’ 시트로 질문을 주거나, ‘질문 만들기’ 프롬프트로 받음(없으면 유형별 기본 질문). 답(그대로 좋음 / 대안이 좋음 / 수정 필요)을 채워 올리면 반영 — 바뀐 줄은 새 버전 → 독립 역번역·검수·사람 승인 다시.
  - ③ 최종 번역 엑셀 다음 장 ‘번역 이유’: 같은 순서(같은 문구는 처음 나온 화면에만)로 번역이 전하는 뜻 · 번역 방식 · 왜 이렇게 번역했나(번역 AI 이유 + 사람이 고른 이유 + 예외 사유) · 핵심 단어 선택 · 다른 선택지와 고른 이유 · 바뀐 이력 · 검수 결과(역번역) · 특이사항(재설계·재구성·현지화·영어 유지·단어 의미) · 상태. 이유 기록이 없는 줄은 노란 칸으로 표시.
  - 번역 이유 정리 (v19): 직역이면 ‘직역’ 한 단어만 (일반적인 ‘그대로 옮김’ 설명은 지움, 단어 선택·대비가 있으면 남김). 같은 줄이 다른 화면에 또 나오면 ‘↑ 화면과 같음’, 다른 줄인데 이유가 같으면 ‘R020 줄과 같은 이유’(회색). ‘자연스러워서’ 같은 추상적 이유는 ‘(이유 없음)’(노란 칸)으로, 화면 머리줄에 ‘이유 없음 n줄 → 번역 근거 다시 받기’. 근거 칸은 한 줄(방식 · 핵심어 최대 3개 · 검수 · 역번역), 이유 칸과 겹치는 방식은 다시 안 씀. 번역 이유 시트의 ‘뜻’ 칸은 원문과 같거나 자리 표시면 비움.
  - **함께 볼 화면 묶음 (v19)**: 게임 이해 AI가 ‘화면 묶음’ 시트(묶음 이름 | 화면 ID들 | 왜 같이 봐야 하나)를 냄. ① 게임 정보의 ‘함께 볼 화면 묶음’ 칸에서 `이름 | ID들 | 이유` 한 줄씩 고침(고치면 이해 확정이 풀림). 번역·검수·원문 프롬프트에 ‘묶음 안의 이미지는 모두 한꺼번에 본 뒤 번역, 한 묶음을 둘로 쪼개지 않음’이 들어가고, 맥락 검수에 ‘묶음 …’(함께 볼 화면) 그룹이 생김. 독립 역번역에는 넣지 않음.
  - ③ 최종 번역 첫 장 열: 화면 ID · 순서 · 요소 · 번호 · 한국어 원문 · 최종 번역 · 번역 이유 · 근거(방식·핵심어·뜻·검수·역번역) · 상태 (화면 이름·이미지 열은 뺌)
  - ③ 최종 번역 엑셀(언어별 — 보고 있는 언어 하나만, 파일 이름에 언어): 화면별(게임 이해의 화면 순서) · 화면 안 등장 순서 · 합친 문구는 화면마다 다시 풂 · 모든 줄에 지금 번역을 넣고, 확정(사람 승인 + 현지인 검수 대상이면 현지인 확인)된 줄은 ‘확정’, 아직인 줄은 노란 칸 + ‘미확정(지금 번역)’, 번역이 아예 없는 줄은 빨간 칸 ‘(번역 없음)’. 화면마다 ‘n/m 확정’.
- **검수 구조 재설계 (v17)** — 언어를 모르는 담당자가 판단할 수 있게:
  - 사람 검수: 줄마다 ‘언어 정확성’과 ‘게임 기능’을 따로 판정, 문제 유형(번역 오류·의미 불일치·문맥 오류·용어 불일치·말투·누락·추가·기능·UI·표기·방식 판정·판정 번복·원문 확인) 칩, 판정 신뢰도(근거가 몇 개 맞는지 사이트가 계산: 독립 역번역 일치 / 프로그램 점검 / 번역·검수 AI의 방식 판정 일치 / 맥락 검수 / 점수가 경계에서 먼지 / 판정 번복 없음 / 번역 AI≠검수 AI). AI가 스스로 매긴 확신도는 쓰지 않음.
  - 엑셀: 검수 결과 엑셀 첫 시트 ‘검수 작업’ — 우선순위(치명 → FAIL → HOLD → REVIEW → 신뢰도 낮음 → 미검수 → PASS) 순, 왼쪽 5열·첫 행 고정, 필터, 상태·판정·신뢰도 색, ‘사람 결정’ 목록(승인·수정·보류·수정 요청) + 사람 수정 번역 + 메모. 채워서 ‘작업표 올리기’로 다시 올리면 반영(확인값으로 그 사이 바뀐 줄은 거름, 승인 조건은 화면과 같음, 수정은 새 버전 → 다시 검수).
  - 교차 검증: 번역 AI / 독립 역번역 AI(원문 없음) / 검수 AI / 맥락 검수가 서로 다른 입력으로 따로 판단하고 사이트가 대조. 번역 AI = 검수 AI면 ‘역할 분리 안 됨’ 경고.
  - 불일치 방지: 번역 방식(직역·의역·재구성)을 검수 AI도 따로 판정 → 다르면 REVIEW / 번역은 그대로인데 방식 판정만 바뀌면 REVIEW(근거 표시) / 같은 원문인데 줄마다 방식이 다르면 REVIEW / 같은 번역에 대한 검수 판정이 예전과 달라지면 ‘판정 번복’ REVIEW / 다른 게임에서 사람이 승인한 같은 원문의 번역과 다르면 REVIEW / 고친 번역에 이유가 없으면 형식 오류로 버림.
  - 맥락 검수(④ 탭): 사이트가 묶음을 자동으로 만듦(같은 화면 · 같은 확정 용어가 여러 화면에 · 다른 화면의 비슷한 문구). 검수 AI가 묶음 단위로 용어 불일치 · 기능 연결(버튼·안내·메시지) · 순서·흐름 · 말투 변화 · 표현 불일치를 봄. 모든 묶음에 답해야 하고(빠지면 다시), 번역이 바뀐 묶음은 다시 검수 대상. 문제는 해당 줄의 자동 점검(FAIL/REVIEW)으로. 새 형식으로 검수한 게임은 맥락 검수 완료가 검수 단계 완료 조건.
- **기초 영어 단어 유지 (v16, 일본어·중국어)**: 허용 목록(처음 값 Same · Front · Side, 관리 화면에서 관리자가 바꿈)은 후보일 뿐 고정 용어집이 아님. 번역 AI가 줄마다 유지/번역을 정하고 ‘영어 유지: 단어 — 이유’를 기록. 자동 점검(REVIEW): 목록에 없는 영어를 번역하지 않음(enOut), 목록 단어를 영어로 뒀는데 이유가 없음(enWhy), 퍼즐·정답 줄에서 영어 유지(enPz). 원문에 원래 영어로 적힌 단어·게임명은 제외. 검수 AI는 일본어·중국어 사용자 모두 바로 이해하는지, 다른 뜻으로 읽히지 않는지(예: 일본어 Front = 호텔 프런트) 확인.
- **검증 3가지 + 역번역 확정 (v15)**: 독립 검수(원문과 번역문이 의미적으로 일치하는가 · 검수 AI 점수) / 역번역(번역문이 실제로 전달하는 의미 · 원문 안 본 AI) / 교차 비교(둘이 모순되지 않는가 · 사이트가 확인: 부정·금지, 숫자, 뜻 전체, 애매한 부분, 검수 AI가 원문을 보고 뜻을 되살렸는지). 모순이면 자동 점검 REVIEW + ‘사람이 볼 것’에 올라오고, 유지하려면 사유 필수. 역번역 확정 조건 6가지(핵심 의미 · 행동 및 지시 · 조건 및 제한 사항 · 숫자 및 고유명사 · 누락·임의 추가 없음 · 독립 검수와 모순 없음)를 줄마다 보여 주고 모두 충족 PASS / 하나라도 불확실 REVIEW / 명백히 잘못 FAIL / 원문 자체를 판단할 수 없음 HOLD. HOLD는 검수 AI가 판정 칸에 씀 → 기획 확인 메모 자동, 원문 확인 사유를 쓰기 전에는 승인 불가(서버도 막음). 독립 역번역이 없으면 6번째 조건이 ‘확인 못 함’이라 REVIEW. 검수 결과 엑셀 ‘원문·번역·역번역’ 시트에 교차 비교·역번역 확정 열.
- **재설계 (v14)**: C(재설계 필요) 줄은 가장 가까운 번역이 아니라 같은 기능의 문제로 새로 만듦. 번역 칸에 재설계안, ‘재설계’ 시트에 원래 기능 · 그대로 안 되는 이유 · 재설계 방식 · 재설계안의 뜻 · 바뀐 정답·단서 · 함께 바꿔야 할 것 · 실존 작품 사용. 원칙: 정답·숫자·실물 소품은 되도록 유지, 정답이 바뀌면 관련 줄 모두 함께, 노래 가사는 원곡 번역·실존 가사 복사 금지(전래 동요나 새로 쓴 가사, 실존 노래를 쓰면 이름을 적고 기획이 저작권 확인), 문화 지식은 현지의 같은 종류 지식으로(정치·역사·종교·실존 인물 금지). 올리면 C 줄에 ‘[기획 확인] 재설계안 확인’ 메모가 자동으로 붙음(기획 승인 전 확정 불가). 독립 검수는 재설계 줄을 원문의 뜻이 아니라 원래 기능 기준으로 채점하고, 바뀐 정답이 실제로 풀리는지·관련 줄과 맞는지를 정답 칸으로 봄. 재설계 줄의 부정·행동 관계 변화는 프로그램 점검에서 REVIEW.
- **엑셀 정리**: 통합 검수 엑셀(모든 언어) 버튼은 없앰. 언어별 ‘검수 결과 엑셀’에 번역 · 원문·번역·역번역(+3분류) · 직역·의역·재창조 비율(수식) · 수정 이력(버전 변경, 남은 FAIL·REVIEW, 예외 유지, 수정 요청 메모) 시트가 들어감. 원문 분석·정답 기준·용어집은 엑셀로 받지 않음(사이트에서 확인). 통합 엑셀 코드(specXlsx·gameXlsx)는 남아 있지만 화면에서 부르지 않음.
- **번역 대안 · 사람의 선택 (v13)**: 번역 AI가 해석·표현에 따라 번역이 달라지는 줄에만 ‘번역 대안’ 시트(기본 + 대안 2~4개, 대안마다 한국어 의미·뉘앙스·직역/의역·쓸 상황·원문과 차이·캐릭터 적합성·추천)를 냄. 2단계 ‘번역 대안’ 패널에서 ‘이걸로 쓰기’·‘지금 번역 유지’·‘추가 대안 요청’(고른 줄만 담은 프롬프트). AI 추천과 다른 최종 번역이면 이유 한 줄 필수. 고르면 새 버전(종류 ‘대안 선택’, 오류 이력에서 빠짐)이 되고 그 줄만 다시 검수. 같은 어구로 묶인 줄은 함께 바뀜. 고르지 않으면 지금 번역으로 진행.
- **독립 역번역 (v13)**: 독립 검수 전에 원문·게임 설명·PNG 없이 번역문만 보내는 역번역 프롬프트. 결과(`bt0`)는 번역 해시에 묶여 번역이 바뀌면 무효. 검수 프롬프트에 ‘독립 역번역’ 열로 들어감. 건너뛰면 상세 화면에 ‘원문을 본 검수 AI의 역번역’으로 표시.
- **의미 일치도 100점 + 치명 오류 (v13)**: 검수 AI가 5개 항목(핵심 의미 35 · 행동 의도 20 · 대상·조건 20 · 문맥 15 · 말투 10)을 정해진 네 값(온전·경미·일부 손실·손실) 중에서 고르고 근거를 씀. 합계는 사이트(와 서버)가 계산. 판정은 사이트가 정함: 치명 오류(부정 반전 등 8종) 또는 정답·추가 정보·용어 FAIL → FAIL / 70 미만 FAIL / 70~89 REVIEW / 90 이상 PASS(90~94 주의). 점수는 판정을 내리기만 하고 올리지 않음(AI 판정보다 엄격한 쪽). 기준값은 관리 화면 ‘검수 판정 기준’에서 바꿈(관리자만, 서버가 막음), 검수 결과에 그때 기준이 저장됨. 프로그램 점검에 ‘부정 누락’(FAIL) 추가. 치명 오류가 있는 줄은 예외 사유 없이 승인하면 서버가 승인을 지움. 예전 9칸 형식 결과도 그대로 읽힘.
- **존대·반말·대화체 일관성 (v12)**: 번역·검수 프롬프트 모두에 공통 원칙 + 언어별 규칙(중국어 您/你·请·语气词, 일본어 です・ます/보통체·경어, 영어 Please·지시 강도)이 들어감. 검수 항목에 9번째 ‘말투’ 칸 추가(말하는 문장이 아니면 해당 없음). 불일치면 PASS 불가, 이유에 차이와 수정 방향. 사이트 자동 점검(REVIEW): 한국어 문장 끝(…요/…니다 ↔ …해/…자)과 일본어 문장 끝(です・ます ↔ 보통체)이 다르면 표시, 중국어는 원문 반말인데 您이 있거나 게임 안에서 您과 你가 섞이면 표시. 일본어 ‘명령형 금지’ 규칙은 유지하되 원문이 반말 지시면 ～て・～てね로 쓰도록 정리. 캐릭터별 일관성은 게임 정보의 ‘화자별 말투’를 기준으로 함.
- **검수한 원문 다시 쓰기 (v11)**: 검수 AI가 줄마다 역번역 바로 앞에 그 번호의 한국어 원문을 다시 씀. 번호·확인값은 맞는데 내용만 밀린 경우(번호·확인값은 기계적으로 복사돼서 확인값만으로는 못 잡음)를 이걸로 잡아 반영하지 않음. 이미 들어간 결과는 역번역·고친 번역을 앞뒤 줄과 비교(FAIL)하고, 이웃을 못 찾아도 역번역이 원문과 거의 안 겹치면 REVIEW ‘다른 줄 결과일 수 있음’. 밀림 의심 줄은 ‘사람이 볼 것’에 경고가 뜨고 ‘고친 번역 쓰기’가 막힘.
- **줄 밀림 방지**: 결과의 확인값이 다른 줄의 것이면 ‘줄 밀림’으로 반영하지 않음. 확인값이 없는 예전 형식이면 역번역이 자기 원문보다 앞뒤 줄 원문과 훨씬 비슷할 때 반영하지 않음. 이미 밀려 들어간 결과는 자동 점검에 FAIL ‘검수 결과가 한 줄 밀려 붙었을 수 있음’으로 뜨고, ‘모두 지우고 다시 검수’ 한 번으로 그 줄만 다시 검수 대상이 됨. 이미 검수된 줄은 예전 결과 파일로 덮어쓰지 않음. 새 검수 결과가 들어오면 그 줄의 사람 판정은 무효.
- **서버 확정 문**: 원문 기준 언어는 모든 줄이 지금 번역문 기준으로 사람 승인돼야 확정(진행 4)으로 올라감. 원문 기준 게임에는 ‘이미 끝났으면 완료 처리’ 버튼이 없음.
- **확정 뒤 변경**: 확정된 언어에서 번역·검수·승인이 바뀌면 자동으로 검수 단계로 되돌리고 알림(자동 삭제 기한도 해제).
- **줄 짝짓기**: 번역 엑셀은 ID + 원문으로 맞춤. 같은 ID인데 원문이 많이 다르면 줄이 밀린 것으로 보고 원문으로 다시 맞춤(토스트에 표시), 조금 다르면 ID를 믿고 ‘원문 다름’ REVIEW. 다시 올릴 때 검수·승인은 ID 기준으로 이어받음(예전 방식은 같은 문구의 순번까지 맞춤).
- **동시 편집**: 같은 줄에서 한 칸이라도 충돌하면 그 줄의 내 변경 전체를 반영하지 않음(수정 이력만 붙는 반쪽 반영 없음). 엑셀을 올리는 동안 들어온 다른 사람의 변경을 되돌리지 않음.
- **원문 다시 올리기**: 새로 생긴 원문 줄은 언어별 번역 표에 빈 줄로 들어가 ‘번역 필요’로 잡힘.
- **같은 문구는 원문표에 한 번만**: 원문 분석 엑셀을 올리면 같은 문구는 **자동으로 한 줄로 합침**(파일 칸에 나오는 파일 모두, 화면 칸에 파일별 위치). 화면마다 번역이 달라야 하는 줄만 원문 분석 엑셀 비고에 ‘분리 사유: …’를 쓰면 따로 남음.
  - 합친 줄의 비고에 ‘N번 반복 (S006·S011·S016 합침)’이 남고, 번역 프롬프트의 원문표에도 ‘N번 반복되는 문구 · 모든 화면 같은 번역’으로 들어감.
  - 예전에 올려 이미 여러 줄로 들어간 게임: 편집 권한이 있는 사람이 게임 화면을 열면 자동으로 합침(버튼 없음). 이미 번역된 언어도 그 줄로 정리되고, 없어진 줄의 메모는 남은 줄로 옮겨지며, 정답 기준의 관련 ID도 바뀜. 같은 분류로 모두 승인된 줄끼리면 원문 확정 유지, 분류가 달랐던 묶음만 다시 승인.
  - 합친 줄들의 번역이 서로 달랐으면 남은 줄에 ‘합친 줄의 번역이 달랐음’ REVIEW로 알려 줌(어느 번역으로 통일할지 사람이 확인).
- 판정은 그 게임의 용어집·이미지 기준(현황판·검색에서 다른 게임을 골라도 같음). 예외 사유가 있는 FAIL은 판단 근거에 노란색으로 표시.

### 행동 관계 검수 (누가 → 누구에게 : 무엇을, 규칙 버전 `2026.11-v7`)

한국어는 주어를 자주 빼서, 단어는 맞는데 행동 방향만 뒤집히는 오역이 생김 (예: ‘병원에서 엄마에게 전화해 알려준다’ → ‘엄마가 전화해서 알려준다’). 글자 비교로는 안 잡혀서 따로 대조함.

1. **원문 준비**: 원문 분석 엑셀의 `행동 관계` 열 = `주체 → 대상 : 행동` (생략된 주어를 여기에만 채움, 원문 문장은 그대로). 사람이 승인한 정답 기준. ‘문맥 확인 필요’면 사람이 볼 줄로 올라옴.
2. **독립 검수**: 검수 AI가 원문을 보기 전에 번역문만 읽고 `번역문 관계` 열에 같은 형식으로 씀.
3. **프로그램 대조**: 주체·대상이 뒤바뀌면 **FAIL**(고치거나 예외 사유 필요, 승인 불가), 표현이 다르면 **REVIEW**, 같으면 PASS. 번역이 바뀌면 검수 AI 관계도 지워지고 다시 받음.
4. **화면·엑셀**: 사람 승인 카드에 원문 기준 / 번역문 관계가 나란히. 엑셀 02 P열(원문 관계), 03~05 AF·AG·AH열(원문 관계 · 번역문 관계 · 대조 결과), 11 상세 통계에 뒤바뀜·확인 필요 수.

- 한계: 검수 프롬프트에 원문도 함께 들어가므로 ‘먼저 쓰기’ 순서는 AI가 지키게 하는 것이고 완전한 블라인드는 아님. 파일럿에서 놓치는 사례가 나오면 번역문만 주는 별도 단계로 분리.

### 전체 통계 = 직역 · 의역 · 재창조 비율

- 엑셀 첫 통계 시트와 사이트 2단계 막대는 세 가지만 보여 줌: **직역**(그대로 번역하면 됨) / **의역**(뜻을 살려 표현을 바꿔야 함) / **재창조**(번역이 아니라 문제를 새로 만들어야 함).
- 기준: 원문 분석의 현지화 분류(A→직역, B→의역, C→재창조). 없으면 번역 AI가 적은 번역 방식(재구성→재창조). 둘 다 없으면 ‘분류 없음’으로 따로 세고 비율에서 뺌(0%로 보이지 않음).
- 비율은 언어 시트의 ‘3분류’ 열을 COUNTIF로 계산하는 수식. 검수·승인 지표는 맨 뒤 ‘상세 통계’ 시트로 옮김.

### 번역 데이터 통합 관리 (번역 · 근거 · 검수 · 버전)

한 항목(고유 ID × 언어)에 원문 정보 · 번역 정보 · 검수 정보 · 변경 이력이 모두 묶임. 사이트가 기준 데이터이고 엑셀은 출력물.

- **버전**: 번역문이 바뀌어도 덮어쓰지 않음. 같은 ID 안에서 V1(최초 번역 엑셀) → V2 … 로 쌓이고, 버전마다 그때의 번역문 · 번역 근거 · 검수 결과(역번역·판정) · 사람 판정을 보관. 기록에 없는 버전·검수는 만들지 않으며, 근거가 없는 버전은 ‘근거 기록 없음’으로 표시.
  - 바뀌는 곳: 사람 직접 수정, 검수 AI 수정안 반영, 사람 수정 요청 반영, 번역 엑셀 다시 올림.
  - 바뀌면 AI 검수·사람 승인이 무효가 되고 재검수 대상이 됨. 옛 근거는 새 번역에 붙이지 않음 → ‘근거 없는 버전’(REVIEW).
- **근거 다시 받기**: 검수 단계 맨 위 노란 상자. 바뀐 줄만 모아 번역 AI에게 새 근거(번역 방식·한국어 의미·핵심어·이유)와 변경 유형(표현/의미/기능)·의미 차이를 받음. 지금 번역과 글자가 다른 답은 반영하지 않음.
- **변경 설명(사람)**: 항목 상세에서 변경 유형 · 의미 차이(필수) · 지금 번역의 한국어 의미를 직접 남길 수 있음. 검수 AI 수정안 반영 직후에는 검수 AI 지적으로 추정한 유형이 ‘(추정)’으로 붙음.
- **변경 비교**: 표현 변경 / 의미 변경 / 기능 변경. 기록된 설명이 우선이고, 없으면 변경 전후 한국어 의미를 글자 비교해 ‘자동 비교’로 참고 표시.
- **근거 상태**: 번역 AI 작성 근거 → 검수 AI 확인 근거 → 사람 확인 완료 → 최종 승인. 번역 AI가 적은 의미와 검수 AI 역번역, 또는 핵심어 뜻이 어긋나면 ‘근거 충돌’ → 일괄 승인에서 빠지고 한 줄씩 확인.
- **항목 상세** (줄 번호·‘상세’ 누르기): ① 최종 번역 정보 ② 번역 판단 상세(가능한 해석·채택·채택하지 않은 해석·이유) ③ 검수 결과(두 의미의 차이·오류 지적·최종 판정) ④ 변경 이력(버전표·전후 비교). 상세 근거는 펼쳐 봄.
- **번역 검색** (위 메뉴): 원문 · 번역문(이전 버전 포함) · 단어 의미 · 번역 이유 · 한국어 의미, 게임·언어·번역 방식, 재구성 / 수정 이력 / 검수 오류 / 근거 충돌 / 근거 없는 버전 / 미해결. 단어로 찾으면 그 단어가 문맥마다 어떤 뜻으로 판단됐는지 모아 보여 줌(예: Check → 확인하다 / 체크 표시 …).
- **엑셀**: 06에 변경 전후 한국어 의미·방식·변경 유형·의미 차이·재검수 여부(N~T열), 09 번역 버전, 10 확인 사항(미해결 오류·근거 충돌·근거 없는 버전·확인 필요).

### 외국어를 몰라도 판단하기 (규칙 버전 `2026.11-v6`)

사람 승인 카드 한 장에 한국어 근거만 모아 둠. 번역문은 읽지 못해도 됨.

- **의미 대조**: 원문 → 원문 핵심 의미(원문 준비) → 번역 AI가 적은 의미(번역할 때) → 검수 AI가 읽은 의미(역번역, 번역 AI 설명 없이). 원문과 역번역에서 한쪽에만 있는 말을 뽑아 보여 줌(글자 비교라 참고용).
- **핵심어 대조**: 번역 AI `원문 단어 → 번역어(읽는 법) = 뜻` ↔ 검수 AI `번역어(읽는 법) = 이 문장에서의 뜻`. 일본어·중국어는 한글로 읽는 법을 붙여 화면 이미지와도 맞춰 볼 수 있음.
- **판단 근거 목록**: ✓ 일치 / ! 확인 / ✗ 승인 불가 — 의미 대조 · 검수 AI 8가지 · 프로그램 검사 · 핵심어 · 번역 근거 · 원문 해석 · 현지화 분류. 맨 아래 한 줄 판단(승인 근거 충분 / 노란 항목 확인 후 승인 / 승인 불가).
- 승인·수정 요청할 때 그때 본 판단 근거가 같이 저장됨. 명세 엑셀 03~05의 AA~AD열(핵심어 대응·핵심어 뜻·판단 근거 요약·승인 때 본 근거).
- 파일 단위 일괄 승인 표도 원문 · 역번역 · 핵심어 뜻을 나란히 보여 줌.

### 번역 판단 및 근거 기록

- **원문 준비**에서 한 번만: 원문 핵심 의미, 다의어·중의 판단(채택 의미와 이유, 모르면 ‘문맥 확인 필요’ → 사람이 볼 줄로 올라옴). 세 언어 번역이 같은 해석을 따름.
- **번역 AI**는 모든 줄에 `번역 방식(직역/의역/재구성) | 번역 결과의 한국어 의미 | 단어 의미 판단 | 번역 이유 | 재구성 사유 | 검수 주의사항`을 한국어로 씀(번역할 때의 확인용). 답이 잘리면 파일 단위로 나눠 받음.
- **독립 검수 AI**는 이 근거를 받지 않고 따로 역번역함. 사람 승인·검수 화면에 ‘번역 AI가 적은 의미(번역할 때)’와 ‘검수 AI가 읽은 의미(역번역)’가 나란히 나옴 → 어긋나는 줄을 먼저 봄.
- 자동 점검(REVIEW 등급): 번역 방식·한국어 의미·이유 누락, 한국어 의미가 원문 반복, 이유가 추상적(‘자연스러워서’ 등), 재구성인데 사유 없음, 분류 A인데 재구성·C인데 직역, ‘문맥 확인 필요’ 표시.
- 명세 엑셀: 02에 핵심 의미·다의어 판단(N·O열), 03~05에 근거 6열(U~Z열), 01에 번역 방식 비율·근거 누락 수.

### 판정 체계 (설계 명세 v1.0)

- **프로그램 검사(O)**: FAIL 등급 = 번역 누락 · 변수 · 숫자(B·C 줄이나 주의점에 ‘숫자 변경 허용’이면 REVIEW) · 확정 용어 · 금지 표현 · 한글 남음 · 다른 문자 · 원문 변경. REVIEW 등급 = 특수 기호 · 줄 수 · 길이 · 같은 원문 다른 번역 · 판독 불확실 등. FAIL은 고치거나 **예외 사유**를 써야 넘어감.
- **독립 검수 AI 8가지**: 의미 · 행동 · 조건 · 정답 · 자연스러움 · 문화 · 추가 정보 · 용어 (각각 PASS / FAIL / REVIEW, 정답은 해당 없음 가능). 검수 AI에는 번역 AI의 비고·대안·설명을 주지 않고, 확정 용어집과 정답 기준을 줌.
- **형식 오류·응답 누락**: 판정 칸이 비었거나 허용되지 않은 값이면 REVIEW가 아니라 시스템 오류로 기록하고 그 줄은 검수 미완료로 남김 → 다음 검수 프롬프트에 그 줄만 다시 들어감(재시도).
- **종합(P)**: 프로그램 FAIL 또는 AI FAIL → FAIL / FAIL 없이 REVIEW → REVIEW / 모두 PASS → PASS.
- **AI FAIL 유지**는 예외 사유 필수. 처음 AI 판정은 기록에 남음(통계는 처음 판정 기준).
- **사람 최종 승인(Q)**: 승인 / 수정 요청(오류 유형 + 사유 필수) / 보류. A 분류 · 종합 PASS 줄은 파일 단위로 목록을 보고 한 번에 승인, 나머지는 한 줄씩. AI FAIL·프로그램 FAIL이 남은 줄은 승인 불가. 모든 줄을 승인해야 ④ 확인 가능하고, 이 단계는 ‘완료 처리’로 건너뛸 수 없음.
- **승인 근거**: ‘역번역’(이 언어를 못 읽음) / ‘언어 가능자’(번역문을 직접 읽음). **AI PASS 신뢰도**는 언어 가능자 판정만으로 계산하고 30건 미만이면 참고용으로 표시.
- **상태(T)**: 미검수 / AI 검수 완료 / 사람 검토 중 / 수정 필요 / 재검수 필요 / 최종 승인. 번역을 고치면 이전 PASS와 사람 승인을 이어받지 않고 재검수.
- 메인 화면 게임 이름 아래: 원문 수 · 분류 확정률 · 사람 승인률 · 미해결 오류 수.

### 통합 검수 엑셀 (자료실 → ‘통합 검수 엑셀 (모든 언어)’)

**원문 기준 게임**은 명세 v1.0 구조로 나옴: `00 사용 안내 · 01 전체 통계 · 02 원문 분석(A~M) · 03~05 언어별 번역·검수(A~T, 같은 열 구조) · 06 오류 및 수정 이력 · 07 용어집 · 08 정답·게임 규칙`. 01의 비율은 언어별 시트를 COUNTIF로 계산하는 수식이고, 06에는 수정·미해결·예외 승인이 모두 남음. 엑셀은 전달용이고 기준 데이터는 사이트임.

아래는 **예전 방식 게임**의 4개 시트 구성:

| 시트 | 내용 |
| --- | --- |
| ① 전체 통계 | 언어별: 원문 수 · 번역 완전성 · A/B/C 개수와 비율 · 사람 확인 필요 비율 · 의미 일치율 · 규칙 보존율 · 현지화 적합률 · AI PASS/FAIL/REVIEW · 사람 최종 승인 수 · 재검수 필요 수. **엑셀 수식(COUNTIF)이라 시트를 고치면 다시 계산됨** |
| ② 원문 분류 | 줄마다 언어별 분류·근거·변경 방향·규칙 유지·재설계 여부, 가장 높은 위험 |
| ③ 번역·역검증 | 한 줄 = 원문 한 문장. 언어별 분류 · 번역 · 역번역(검수 AI) · 의미 · 규칙 · 현지화 · AI 판정 · 최종 판정(사람) |
| ④ 수정 이력 | 수정 전후 · 사유 · 누가 · 언제, 미결 FAIL·REVIEW, 사람 판단, 수정 요청 메모와 반영 여부 |

- **AI PASS와 사람 승인을 구분함**: 최종 판정은 ‘AI PASS · 사람 미확인’ / ‘승인(사람 판단)’ / ‘확정 승인(확정한 사람)’ / ‘미결’ / ‘수정됨 · 재검수 필요’.
- 고친 문장은 검수 결과가 지워져 다시 교차 검수를 받아야 함(재검수 필요로 집계).
- 언어마다 원문을 따로 뽑기 때문에 (파일 + 원문)이 같은 줄끼리 한 행으로 맞춤. 뽑는 방식이 달라 맞지 않은 줄은 따로 한 행씩 나옴.

### 특수 규칙 메모 (게임 정보 단계)

청개구리 게임(지시와 반대로 골라야 정답)처럼 AI가 ‘오류’로 착각하기 쉬운 규칙을 적는 칸.

- 칸: 이름 · 적용 화면(파일 이름, 비우면 게임 전체) · 규칙 · AI가 하면 안 되는 것 · 언어별 처리(선택)
- 번역 프롬프트와 교차 검수 프롬프트에 ‘# 특수 규칙’으로 들어감. 언어별 처리는 그 언어 프롬프트에만 들어감.
- 교차 검수 표에서 적용 화면의 줄 비고에 `[특수 규칙: 이름]`이 붙고, 검수 AI는 그 줄을 규칙대로 쓴 것으로 보고 오류로 고치지 않음.
- ‘처음 보는 사람’ 테스트에는 넣지 않음 (규칙을 알려 주면 테스트가 의미 없어짐).

### 검수 AI별 프롬프트

교차 검수 · 글자 대조 · 처음 보는 사람 단계마다 **검수 AI**를 고를 수 있음(Claude / ChatGPT / Gemini). 고른 AI에 맞춰 프롬프트가 바뀜.

- **공통 지시**(모든 AI 같음): 한국어를 모르는 현지 방문객 대상 · 게임 규칙과 정답 보존 · PASS / FAIL / REVIEW · 모든 문장 역번역
- **Claude**: 전체 문맥 먼저 파악 → 문장별 검수 · 의미 차이를 구체적으로 설명 · 문제 없는 문장은 고치지 않음
- **Gemini**: 이미지의 실제 배치와 표 대조 · 이미지에서 확인 못 하는 건 추측 금지 · 글자 누락·이미지 불일치는 ‘[이미지]’로 따로 표시
- **ChatGPT**: 시트·열 이름과 순서 엄격 유지 · 줄마다 PASS / FAIL / REVIEW 구분 · FAIL엔 수정안과 이유를 함께
- 기본값: 교차 검수·글자 대조 = 번역 AI의 반대(ChatGPT ↔ Claude), 처음 보는 사람 = Gemini. 교차 검수 AI가 번역 AI와 같으면 경고가 뜸.

### 중국어: 영어 번역본 보조 참조 (3개 언어 대조)

- 자료 우선순위: **한국어 원문 → 확정 영어(보조 참조) → 중국어**.
- 영어가 4단계 **확정된 뒤에만** 중국어 프롬프트에 영어 표가 들어감. 확정 전이면 2단계에 ‘영어 먼저 확정 권장’ 안내가 뜨고, 영어 없이 진행됨.
- 영어 비고에 재설계·현지화·말장난 등이 적힌 줄(또는 영어 검수에서 기획 확인된 줄)은 ‘영어판 재설계 · 참조 금지’로 표시해서 중국어가 따라가지 않게 함.
- 중국어 번역·교차 검수 프롬프트에 영어 참조 지침 8개가 들어감. 용어집도 중국어 칸 옆에 영어를 함께 보여 줌.
- 중국어 교차 검수의 `줄 검수`에 **불일치** 열이 추가됨: 없음 / 원문≠중국어(FAIL) / 원문≠영어 / 표현 차이 / 판단 불가(REVIEW, 원문 확인 필요).
- **원문≠영어**로 나온 줄은 영어 화면의 같은 문장에 수정 요청 메모(‘중국어 검수에서 발견’)가 자동으로 남음. 영어는 이 메모를 반영해야 ‘화면 적용 완료’ 가능.
- 별도 ‘GPT 최종 정리’ 단계는 두지 않음. 검수 AI의 수정안을 사람이 줄마다 고르는 기존 방식을 그대로 씀.

### 퍼즐 검수 (게임 단위 6가지)

교차 검수 엑셀에 `퍼즐 검수` 시트가 함께 나옴. 퍼즐마다 아래 6가지를 OK / 문제 / 확인 필요 / 해당 없음으로 판정.

| 항목 | 확인할 내용 |
| --- | --- |
| 정답 보존 | 번역 후에도 기존 정답이 유지되는가 |
| 풀이 가능성 | 현지 언어로도 같은 방식으로 풀 수 있는가 |
| 단서 보존 | 정답을 유도하는 정보가 사라지지 않았는가 |
| 언어유희 | 직역으로 퍼즐의 기능이 사라지지 않았는가 |
| 조합 관계 | 문자·숫자·기호의 연결 방식이 유지되는가 |
| 협동 요소 | 1P·2P 정보가 정상적으로 연결되는가 |

- 사이트가 표로 보여 주고, 문제·확인 필요는 **수정 요청 메모(퍼즐)**로 넘김 → 반영해야 확정 가능.
- AI 판정과 관계없이 퍼즐마다 담당자가 직접 풀어 보고 **‘직접 확인함’**을 눌러야 교차 검수 완료 가능.
- 언어유희처럼 재설계가 필요한 건 `[기획 확인]`으로 와서 ‘기획 승인’이 필요함.
- 5단계 ‘처음 보는 사람’ 테스트도 같은 6가지 기준으로 판단 (AI에게 정답에 이른 단서와 1P·2P 정보까지 쓰게 함).

### 기획 확인 (AI가 제안한 기획 변경)

- 교차 검수 AI는 아이콘 교체·퍼즐 재설계·정답 변경을 정하지 않고, 해당 줄을 `[기획 확인]`으로 표시하게 되어 있음.
- 사이트가 이런 줄을 번역 오류와 따로 분리해 **수정 요청 메모(기획 확인)**로 넘김. 특정 줄이 아닌 시트 단위 제안은 ‘시트·전체’ 항목으로 뜸.
- ‘기획 승인’을 누르기 전에는 그 줄의 ‘고친 번역 쓰기’가 막혀 있고, 확정도 안 됨. 승인한 사람과 시간이 기록됨.

### 여러 명이 동시에 작업할 때

- 저장은 바뀐 부분만 서버로 보내고, 서버가 최신본에 합침. 서로 다른 칸을 동시에 고쳐도 둘 다 남음.
- **같은 칸**을 두 사람이 거의 동시에 고치면 먼저 저장된 값을 지키고, 나중 사람에게 “다른 사람이 같은 칸을 먼저 고침” 알림이 뜸. 화면의 최신 내용을 보고 다시 하면 됨.

### 자료 보관 기한

- 번역할 언어(불가능 표시 제외)가 **모두 ‘화면 적용 완료’**가 되면, 그날부터 **30일 보관**.
- 삭제 **7일 전부터** 로그인할 때마다 알림 창이 뜨고, 현황판·게임 화면에 D-day가 표시됨.
- 기한이 지나면 **게임 정보(이름·컨셉·상황·말투·언어 가능 여부)와 진행 표시만 남기고** 엑셀·이미지·검수 기록·메모를 삭제함. 용어집과 폰트는 지우지 않음.
- 알림 없이 지워지지 않도록, 삭제일은 서버가 완료를 처음 확인한 날로부터 최소 7일 뒤로 잡음.
- 완료 후 다시 ‘처음부터 다시’를 하거나 단계를 되돌리면 삭제 예정이 자동으로 취소됨.
- 지운 파일도 GitHub `data` 브랜치 기록에는 남아 있어서 필요하면 되살릴 수 있음.

### 폰트

- **폰트** 탭: 언어별로 쓸 폰트를 정해 두는 곳. 용도(제목·본문 등)·굵기·받는 곳 링크·라이선스 메모 + 파일(TTF·OTF·WOFF·ZIP, 20MB 이하).
- 올린 폰트는 그 언어 예문으로 미리보기가 나옴. 상업용 폰트는 라이선스 칸에 공유 가능 범위를 꼭 적기.

## 운영 (관리자)

**회원 관리 → 운영 점검**

- GitHub 토큰 만료일 표시 (14일 이내면 빨간색). 만료되면 저장이 모두 멈추므로 미리 새 토큰을 만들어 Render의 `GITHUB_TOKEN`을 바꾸기.
- **데이터 백업 받기**: 게임·용어집·폰트 목록을 JSON 파일로 받음. 큰 작업·배포 전에 받아 두기.
- **백업 파일로 되돌리기**(대표 관리자만): 백업 JSON을 고르면 확인 창 → ‘예’를 누르면 게임·용어집·폰트 목록 전체가 그 시점으로 바뀜. 바뀌기 전 상태도 GitHub 기록에 남음.
- 이미지·엑셀 파일은 백업 JSON에 들어가지 않음. 이 파일들은 GitHub `data` 브랜치의 `files/` 폴더와 커밋 기록으로 되살림.

**Render 무료 요금제**: 15분쯤 아무도 안 쓰면 서버가 잠들고, 다음 첫 접속이 30초~1분 걸림. 로그인 화면에도 안내함. 잠든 동안엔 자료 삭제도 멈췄다가 깨어나면 처리함.

## 설정하기 (관리자 1회)

### 1. GitHub 저장소
1. GitHub → New repository → `checkie-translation` → **Private** → Create.
2. 이 폴더 안의 파일과 폴더(`server.js`, `ai.js`, `package.json`, `README.md`, `public`, `data`)를 올리고 Commit.

### 2. 서버용 GitHub 토큰
1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
2. Repository access: Only select repositories → `checkie-translation`
3. Permissions → **Contents: Read and write**
4. 만료일은 길게(예: 1년). 만든 날과 만료일을 팀 일정에 적어 두기. 사이트의 ‘운영 점검’에서도 만료일을 보여 줌.

### 3. Render 배포
- New → Web Service → 저장소 선택 · Branch `main` · Runtime Node · Build Command 비움 · Start Command `npm start` · Instance Free
- Environment Variables:

| 이름 | 값 | 필수 |
| --- | --- | --- |
| `GITHUB_TOKEN` | 2번 토큰 | 필수 |
| `GITHUB_REPO` | `계정이름/checkie-translation` | 필수 |
| `ADMIN_PASSWORD` | 대표 관리자 비밀번호. **기본값 없음 — 비워 두면 대표 관리자 로그인이 막힘** | 필수 |
| `ADMIN_ID` | 대표 관리자 아이디. 비우면 `yeun` | 선택 |
| `ADMIN_NAME` | 대표 관리자 이름. 비우면 `김예은` | 선택 |
| `SESSION_SECRET` | 로그인 유지용 비밀값(긴 아무 문자). 비우면 토큰·비밀번호로 만듦 | 선택 |
| `ANTHROPIC_API_KEY` 등 | (선택) AI 자동 기능용. 지금 화면 흐름에서는 쓰지 않음 | 선택 |

`ADMIN_PASSWORD`를 바꾸면 모든 사람의 로그인이 한 번 풀림.
