# checkie-translation

체키 성수 게임 번역(영어·일본어·중국어 간체)을 팀이 함께 진행하고 체크하는 사이트.

- 로그인해야 볼 수 있음. 팀원은 사이트에서 아이디로 가입 → 관리자가 **보기 허용 / 편집 허용**을 켬.
- 서버는 Render, 데이터는 이 저장소의 `data` 브랜치에 저장. 모든 저장이 커밋으로 남아서 누가 언제 무엇을 바꿨는지 보고 되돌릴 수 있음.

## 사용법

**게임 번역** 첫 화면 = 게임 × 언어 현황판.

- 칸마다 **가능 / 불가능** 선택. 번역이 불가능한 언어는 ‘불가능’으로 두면 체크 대상과 완료 판단에서 빠짐.
- 칸을 누르면 그 언어의 체크리스트 5단계가 나옴.

1. **게임 정보**: 컨셉·상황·말투 (게임마다 한 번)
2. **번역 엑셀**: 프롬프트 복사 → Claude에 PNG(또는 zip)와 함께 보냄 → 받은 엑셀 올리기 → 같은 PNG도 사이트에 올리기
   - 열: `파일 | 화면 | 요소 | 한국어 원문 | 日本語(또는 English·简体中文) | 비고`. 이름이 조금 달라도 찾음. 대응표·퍼즐 재설계 같은 다른 시트도 보관.
3. **검수** (3가지 모두 해야 확정)
   - ① 자동 점검 ② 이미지 대조 ③ 교차 검수(다른 AI 결과 엑셀 올리기 → FAIL·REVIEW만 사람이 결정)
4. **확정**
5. **적용 검수**: 번역을 넣은 PNG를 `원본이름_en` / `_jp` / `_cn`으로 올림 → 나란히 보기 · 글자 대조 · 처음 보는 사람 테스트 → ‘화면 적용 완료’

각 단계의 **확인 완료** 버튼은 누가 언제 눌렀는지 남음. 다른 곳에서 이미 끝낸 단계는 ‘이미 끝났으면 완료 처리’. 언어별 **처음부터 다시**는 확인 창에서 ‘예’를 눌러야 실행됨.

### 수정 요청 메모

- 줄 옆 **메모**(또는 자료실 ‘번역 표 보기’)에 고칠 점을 적으면 게임 화면 맨 위 빨간 상자에 뜸. 남아 있으면 확정 불가.
- **보기 전용 계정도 메모를 남길 수 있음.** 그 밖의 수정은 편집 허용이 필요.
- 작성자·시간은 서버가 기록함(이름을 바꿔 적을 수 없음). 남긴 메모는 지우거나 내용을 바꿀 수 없고, ‘반영함’ 표시만 가능. 언어를 ‘처음부터 다시’ 할 때만 함께 지워짐.

### 번역 AI · 검수 AI (팀 운영 원칙)

| 언어 | 번역 | 검수 |
| --- | --- | --- |
| 영어 | ChatGPT | Claude |
| 일본어 | Claude | ChatGPT |
| 중국어(간체) | ChatGPT | Claude |

- 사이트 기본값이 이 조합임. 2단계 ‘프롬프트 보기 · 번역 AI 바꾸기’에서 바꾸면 검수 AI도 반대쪽으로 바뀜.
- 교차 검수 프롬프트에 공통 검수 기준 6가지(정확성·누락 여부·자연스러움·용어 통일·캐릭터성·게임 적합성)와 검수 AI별 중점, ‘1차 번역 판단을 따르지 않고 독립 검수’ 원칙이 들어 있음.

### 번역 프롬프트 구성 (규칙 버전 `2026.11-v3`)

번역 프롬프트는 아래 순서로 조립됨. 공통 부분은 코드 한 곳(`COMMON_TRANSLATE`, `TRANSLATE_TIPS`)에서만 고치면 모든 게임·언어에 적용.

1. **공통 지시**: 역할 · 번역 우선순위(규칙·정답 → 의미·행동 → 말투·상황 → 자연스러움 → 글자 수) · 용어 · 의미·규칙 보존 · 문체 · 형식 · 불확실 처리 · 최종 결과
2. **번역 AI별 추가 지시**: Claude(전체 문맥·일관성) / Gemini(이미지 시각 맥락·화면 역할) / ChatGPT(1:1 대응·시트 구조 엄수)
3. **게임별 정보**: 게임 정보 단계의 컨셉·상황·**게임 규칙·정답**(새 칸)·화자별 말투
4. **용어집 · 언어 규칙**(중국어는 간체·영어 참조 블록)
5. **이번 작업 · 결과물**: `번역` 시트에 `역번역` 열 추가, 언어유희처럼 기획 판단이 필요한 건 `기획 확인` 시트(대안 최대 2개)

- `기획 확인` 시트는 엑셀을 올리면 해당 줄의 기획 확인 메모로 바뀜(작성자 ‘번역 AI’) → 기획 승인 전엔 확정 불가.
- 프롬프트 첫 줄에 규칙 버전과 AI 이름이 들어가고, 올린 엑셀에도 어느 버전·어느 AI로 만들었는지 기록됨.
- 번역 AI가 쓴 역번역은 자기 번역을 설명하는 것이라 검증력이 약함. 판단 근거는 교차 검수 AI의 역번역으로 함.
- 엑셀을 다시 올려 줄 번호가 바뀌어도 수정 요청 메모는 그 문장을 따라감. 없어진 문장의 메모는 ‘이전 엑셀’ 항목으로 남음.

### 현지화 분류 (A·B·C)와 비율

번역 엑셀의 모든 줄에 번역 AI가 분류를 붙임: `현지화 분류 | 분류 근거 | 변경 방향 | 원문 규칙 유지 | 재설계 여부`.

| 분류 | 뜻 | 사이트 처리 |
| --- | --- | --- |
| A. 직접 번역 가능 | 그대로 옮겨도 똑같이 이해됨 | 일반 검수 |
| B. 의미 현지화 필요 | 그대로 옮기면 뜻이 안 통함. 규칙은 유지하고 뜻만 현지화 | 자동 점검에 ‘변경 방향 확인’ 항목으로 올라옴 |
| C. 재설계 필요 | 발음·말장난·속담 등에 기대서 번역만으로는 문제 유지 불가 | 기획 확인 메모로 자동 전환 → 기획 승인 전 확정 불가 |

- B·C는 ‘왜 직접 번역이 안 되는지’ 근거가 필수. 근거가 비어 있거나, B인데 원문 규칙 유지가 ‘불가’면 자동 점검에 걸림.
- 분류는 **언어마다** 함(같은 문장도 일본어에선 A, 영어에선 B일 수 있음).
- 2단계에 비율 막대가 나옴: 직접 / 현지화 / 재설계 / 사람 확인 필요(B+C). 번역 난이도 통계이지 품질 점수가 아님.

### 역검증 5가지 (교차 검수)

교차 검수 AI가 줄마다 **의미 · 행동 · 조건 · 정답 · 현지화**를 각각 PASS / FAIL / REVIEW로 판정(정답은 해당 없음 가능). 하나라도 FAIL이면 그 줄은 FAIL, REVIEW가 있으면 PASS로 올리지 않음. 검수 화면에 항목별 결과가 표시됨.

### 통합 검수 엑셀 (자료실 → ‘통합 검수 엑셀 (모든 언어)’)

| 시트 | 내용 |
| --- | --- |
| ① 전체 통계 | 언어별: 원문 수 · 번역 완전성 · A/B/C 개수와 비율 · 사람 확인 필요 비율 · 의미 일치율 · 규칙 보존율 · 현지화 적합률 · AI PASS/FAIL/REVIEW · 사람 최종 승인 수 · 재검수 필요 수. **엑셀 수식(COUNTIF)이라 시트를 고치면 다시 계산됨** |
| ② 원문 분류 | 줄마다 언어별 분류·근거·변경 방향·규칙 유지·재설계 여부, 가장 높은 위험 |
| ③ 번역·역검증 | 한 줄 = 원문 한 문장. 언어별 분류 · 번역 · 역번역(검수 AI) · 의미 · 규칙 · 현지화 · AI 판정 · 최종 판정(사람) |
| ④ 수정 이력 | 수정 전후 · 사유 · 누가 · 언제, 미결 FAIL·REVIEW, 사람 판단, 수정 요청 메모와 반영 여부 |

- **AI PASS와 사람 승인을 구분함**: 최종 판정은 ‘AI PASS · 사람 미확인’ / ‘승인(사람 판단)’ / ‘확정 승인(확정한 사람)’ / ‘미결’ / ‘수정됨 · 재검수 필요’.
- 고친 문장은 검수 결과가 지워져 다시 교차 검수를 받아야 함(재검수 필요로 집계).
- 언어마다 원문을 따로 뽑기 때문에 (파일 + 원문)이 같은 줄끼리 한 행으로 맞춤. 뽑는 방식이 달라 맞지 않은 줄은 따로 한 행씩 나옴.

### 특수 규칙 메모 (게임 정보 단계)

청개구리 게임(지시와 반대로 골라야 정답)처럼 AI가 ‘오류’로 착각하기 쉬운 규칙을 적는 칸.

- 칸: 이름 · 적용 화면(파일 이름, 비우면 게임 전체) · 규칙 · AI가 하면 안 되는 것 · 언어별 처리(선택)
- 번역 프롬프트와 교차 검수 프롬프트에 ‘# 특수 규칙’으로 들어감. 언어별 처리는 그 언어 프롬프트에만 들어감.
- 교차 검수 표에서 적용 화면의 줄 비고에 `[특수 규칙: 이름]`이 붙고, 검수 AI는 그 줄을 규칙대로 쓴 것으로 보고 오류로 고치지 않음.
- ‘처음 보는 사람’ 테스트에는 넣지 않음 (규칙을 알려 주면 테스트가 의미 없어짐).

### 검수 AI별 프롬프트

교차 검수 · 글자 대조 · 처음 보는 사람 단계마다 **검수 AI**를 고를 수 있음(Claude / ChatGPT / Gemini). 고른 AI에 맞춰 프롬프트가 바뀜.

- **공통 지시**(모든 AI 같음): 한국어를 모르는 현지 방문객 대상 · 게임 규칙과 정답 보존 · PASS / FAIL / REVIEW · 모든 문장 역번역
- **Claude**: 전체 문맥 먼저 파악 → 문장별 검수 · 의미 차이를 구체적으로 설명 · 문제 없는 문장은 고치지 않음
- **Gemini**: 이미지의 실제 배치와 표 대조 · 이미지에서 확인 못 하는 건 추측 금지 · 글자 누락·이미지 불일치는 ‘[이미지]’로 따로 표시
- **ChatGPT**: 시트·열 이름과 순서 엄격 유지 · 줄마다 PASS / FAIL / REVIEW 구분 · FAIL엔 수정안과 이유를 함께
- 기본값: 교차 검수·글자 대조 = 번역 AI의 반대(ChatGPT ↔ Claude), 처음 보는 사람 = Gemini. 교차 검수 AI가 번역 AI와 같으면 경고가 뜸.

### 중국어: 영어 번역본 보조 참조 (3개 언어 대조)

- 자료 우선순위: **한국어 원문 → 확정 영어(보조 참조) → 중국어**.
- 영어가 4단계 **확정된 뒤에만** 중국어 프롬프트에 영어 표가 들어감. 확정 전이면 2단계에 ‘영어 먼저 확정 권장’ 안내가 뜨고, 영어 없이 진행됨.
- 영어 비고에 재설계·현지화·말장난 등이 적힌 줄(또는 영어 검수에서 기획 확인된 줄)은 ‘영어판 재설계 · 참조 금지’로 표시해서 중국어가 따라가지 않게 함.
- 중국어 번역·교차 검수 프롬프트에 영어 참조 지침 8개가 들어감. 용어집도 중국어 칸 옆에 영어를 함께 보여 줌.
- 중국어 교차 검수의 `줄 검수`에 **불일치** 열이 추가됨: 없음 / 원문≠중국어(FAIL) / 원문≠영어 / 표현 차이 / 판단 불가(REVIEW, 원문 확인 필요).
- **원문≠영어**로 나온 줄은 영어 화면의 같은 문장에 수정 요청 메모(‘중국어 검수에서 발견’)가 자동으로 남음. 영어는 이 메모를 반영해야 ‘화면 적용 완료’ 가능.
- 별도 ‘GPT 최종 정리’ 단계는 두지 않음. 검수 AI의 수정안을 사람이 줄마다 고르는 기존 방식을 그대로 씀.

### 퍼즐 검수 (게임 단위 6가지)

교차 검수 엑셀에 `퍼즐 검수` 시트가 함께 나옴. 퍼즐마다 아래 6가지를 OK / 문제 / 확인 필요 / 해당 없음으로 판정.

| 항목 | 확인할 내용 |
| --- | --- |
| 정답 보존 | 번역 후에도 기존 정답이 유지되는가 |
| 풀이 가능성 | 현지 언어로도 같은 방식으로 풀 수 있는가 |
| 단서 보존 | 정답을 유도하는 정보가 사라지지 않았는가 |
| 언어유희 | 직역으로 퍼즐의 기능이 사라지지 않았는가 |
| 조합 관계 | 문자·숫자·기호의 연결 방식이 유지되는가 |
| 협동 요소 | 1P·2P 정보가 정상적으로 연결되는가 |

- 사이트가 표로 보여 주고, 문제·확인 필요는 **수정 요청 메모(퍼즐)**로 넘김 → 반영해야 확정 가능.
- AI 판정과 관계없이 퍼즐마다 담당자가 직접 풀어 보고 **‘직접 확인함’**을 눌러야 교차 검수 완료 가능.
- 언어유희처럼 재설계가 필요한 건 `[기획 확인]`으로 와서 ‘기획 승인’이 필요함.
- 5단계 ‘처음 보는 사람’ 테스트도 같은 6가지 기준으로 판단 (AI에게 정답에 이른 단서와 1P·2P 정보까지 쓰게 함).

### 기획 확인 (AI가 제안한 기획 변경)

- 교차 검수 AI는 아이콘 교체·퍼즐 재설계·정답 변경을 정하지 않고, 해당 줄을 `[기획 확인]`으로 표시하게 되어 있음.
- 사이트가 이런 줄을 번역 오류와 따로 분리해 **수정 요청 메모(기획 확인)**로 넘김. 특정 줄이 아닌 시트 단위 제안은 ‘시트·전체’ 항목으로 뜸.
- ‘기획 승인’을 누르기 전에는 그 줄의 ‘고친 번역 쓰기’가 막혀 있고, 확정도 안 됨. 승인한 사람과 시간이 기록됨.

### 여러 명이 동시에 작업할 때

- 저장은 바뀐 부분만 서버로 보내고, 서버가 최신본에 합침. 서로 다른 칸을 동시에 고쳐도 둘 다 남음.
- **같은 칸**을 두 사람이 거의 동시에 고치면 먼저 저장된 값을 지키고, 나중 사람에게 “다른 사람이 같은 칸을 먼저 고침” 알림이 뜸. 화면의 최신 내용을 보고 다시 하면 됨.

### 자료 보관 기한

- 번역할 언어(불가능 표시 제외)가 **모두 ‘화면 적용 완료’**가 되면, 그날부터 **30일 보관**.
- 삭제 **7일 전부터** 로그인할 때마다 알림 창이 뜨고, 현황판·게임 화면에 D-day가 표시됨.
- 기한이 지나면 **게임 정보(이름·컨셉·상황·말투·언어 가능 여부)와 진행 표시만 남기고** 엑셀·이미지·검수 기록·메모를 삭제함. 용어집과 폰트는 지우지 않음.
- 알림 없이 지워지지 않도록, 삭제일은 서버가 완료를 처음 확인한 날로부터 최소 7일 뒤로 잡음.
- 완료 후 다시 ‘처음부터 다시’를 하거나 단계를 되돌리면 삭제 예정이 자동으로 취소됨.
- 지운 파일도 GitHub `data` 브랜치 기록에는 남아 있어서 필요하면 되살릴 수 있음.

### 폰트

- **폰트** 탭: 언어별로 쓸 폰트를 정해 두는 곳. 용도(제목·본문 등)·굵기·받는 곳 링크·라이선스 메모 + 파일(TTF·OTF·WOFF·ZIP, 20MB 이하).
- 올린 폰트는 그 언어 예문으로 미리보기가 나옴. 상업용 폰트는 라이선스 칸에 공유 가능 범위를 꼭 적기.

## 운영 (관리자)

**회원 관리 → 운영 점검**

- GitHub 토큰 만료일 표시 (14일 이내면 빨간색). 만료되면 저장이 모두 멈추므로 미리 새 토큰을 만들어 Render의 `GITHUB_TOKEN`을 바꾸기.
- **데이터 백업 받기**: 게임·용어집·폰트 목록을 JSON 파일로 받음. 큰 작업·배포 전에 받아 두기.
- **백업 파일로 되돌리기**(대표 관리자만): 백업 JSON을 고르면 확인 창 → ‘예’를 누르면 게임·용어집·폰트 목록 전체가 그 시점으로 바뀜. 바뀌기 전 상태도 GitHub 기록에 남음.
- 이미지·엑셀 파일은 백업 JSON에 들어가지 않음. 이 파일들은 GitHub `data` 브랜치의 `files/` 폴더와 커밋 기록으로 되살림.

**Render 무료 요금제**: 15분쯤 아무도 안 쓰면 서버가 잠들고, 다음 첫 접속이 30초~1분 걸림. 로그인 화면에도 안내함. 잠든 동안엔 자료 삭제도 멈췄다가 깨어나면 처리함.

## 설정하기 (관리자 1회)

### 1. GitHub 저장소
1. GitHub → New repository → `checkie-translation` → **Private** → Create.
2. 이 폴더 안의 파일과 폴더(`server.js`, `ai.js`, `package.json`, `README.md`, `public`, `data`)를 올리고 Commit.

### 2. 서버용 GitHub 토큰
1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
2. Repository access: Only select repositories → `checkie-translation`
3. Permissions → **Contents: Read and write**
4. 만료일은 길게(예: 1년). 만든 날과 만료일을 팀 일정에 적어 두기. 사이트의 ‘운영 점검’에서도 만료일을 보여 줌.

### 3. Render 배포
- New → Web Service → 저장소 선택 · Branch `main` · Runtime Node · Build Command 비움 · Start Command `npm start` · Instance Free
- Environment Variables:

| 이름 | 값 | 필수 |
| --- | --- | --- |
| `GITHUB_TOKEN` | 2번 토큰 | 필수 |
| `GITHUB_REPO` | `계정이름/checkie-translation` | 필수 |
| `ADMIN_PASSWORD` | 대표 관리자 비밀번호. **기본값 없음 — 비워 두면 대표 관리자 로그인이 막힘** | 필수 |
| `ADMIN_ID` | 대표 관리자 아이디. 비우면 `yeun` | 선택 |
| `ADMIN_NAME` | 대표 관리자 이름. 비우면 `김예은` | 선택 |
| `SESSION_SECRET` | 로그인 유지용 비밀값(긴 아무 문자). 비우면 토큰·비밀번호로 만듦 | 선택 |
| `ANTHROPIC_API_KEY` 등 | (선택) AI 자동 기능용. 지금 화면 흐름에서는 쓰지 않음 | 선택 |

`ADMIN_PASSWORD`를 바꾸면 모든 사람의 로그인이 한 번 풀림.

## 파일 구성

| 파일 | 역할 |
| --- | --- |
| `server.js` | 서버: 로그인·권한·GitHub 저장·병합 저장·메모 보호·자료 보관 기한·백업 |
| `ai.js` | (선택) AI API 호출 |
| `public/index.html` | 사이트 화면 |
| `public/store.js` | 화면 ↔ 서버 저장 (바뀐 부분만 전송) |
| `public/merge.js` | 동시 저장 병합 규칙 (화면·서버 공용) |
| `public/retention.js` | 자료 보관 기한 규칙 (화면·서버 공용) |
| `public/vendor/xlsx.full.min.js` | 엑셀 읽기 (SheetJS, Apache-2.0) |
| `data/themes.json`, `data/terms.json` | 처음 데이터 |

`data` 브랜치 구조: `data/themes.json`(게임) · `data/terms.json`(용어집) · `data/fonts.json`(폰트 목록) · `data/users.json`(회원, 비밀번호는 해시만) · `files/<게임>/`(엑셀·이미지) · `files/_fonts/`(폰트 파일).
